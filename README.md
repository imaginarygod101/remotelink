# RemoteLink 0.2.1 (public test release)
- Download page: https://remotelink-0s35.onrender.com
- Releases: https://github.com/imaginarygod101/remotelink/releases (latest: v0.2.1, with SHA256SUMS.txt)
- Signaling server (default in all 0.2.1 builds): `wss://remotelink-signal.onrender.com`. It runs on Render's free plan, so it sleeps after about 15 min idle and the first connect after that can take about 1 min.

Transparent, consent-based remote desktop. Every session needs on-screen approval by the host; the host always sees a red **SESSION ACTIVE** banner (window also goes always-on-top and retitles itself) with a one-click **End session** button. No background service, no autostart, no unattended access.

## Layout
- `server/` Node.js WebSocket signaling server (`server.js`) + unit tests (`test.js`)
- `desktop/` Electron client (host + viewer): `src/main.js`, `src/preload.js`, `src/renderer.js`, `src/index.html`; packaging config in `package.json`
- `mobile/` Capacitor viewer (Android/iOS). Android debug APK built + emulator-tested; iOS not built (needs a Mac)
- `site/` static download page (deployed as a Render static site; links point at GitHub Release assets), generated by `tools-scripts/make-site.py`
- `tools-scripts/` site generator, signaling RTT probe, Android stats probe; old 0.2.0 tunnel helpers (watchdog, chunked downloader)
- `render.yaml` Render blueprint (free plan) for the signaling service and the static site
- `TEST-RESULTS.md` measured results for 0.2.0 and 0.2.1
- `tests/e2e.sh` loopback end-to-end test; results in `tests/results/`
- `SECURITY.md`, `DEPLOY.md`, `COMPATIBILITY.md`

## Flow
1. Host clicks *Share my screen* → server issues a random 9-digit code (expires in 10 min).
2. Viewer enters code → host sees a modal with viewer name/IP, *Allow* / *Deny*, and an unchecked "also allow control" box.
3. On Allow, the server issues a per-session token; only token-bearing signaling is relayed. WebRTC (DTLS-SRTP) carries video + a data channel for input.
4. Screen capture is granted by the main process only while a session is approved; input is injected (nut-js) only if the host ticked "allow control".
5. Either side can end; disconnect of either ends the session.

## Run
    cd server && npm i && HOST=0.0.0.0 PORT=8443 node server.js          # plain ws on :8443
    # behind a TLS proxy/tunnel: HOST=127.0.0.1 PORT=8787 TRUST_PROXY=1 STATIC_DIR=../site node server.js
    cd desktop && npm i && npx electron .     # server URL: Settings field (saved in userData/settings.json),
                                              # or RL_SERVER=wss://..., default from desktop/src/defaults.json
Server env: `HOST`, `PORT`, `TRUST_PROXY=1` (use CF-Connecting-IP / X-Forwarded-For), `STATIC_DIR` (serve download page, Range-capable), `ICE_SERVERS` (JSON, default Google STUN), `CODE_TTL_MS`. `/healthz` returns JSON status. Server pings every client every 25 s so idle WebSockets survive proxies.
## Test
    node server/test.js && tests/e2e.sh                  # needs Xvfb + xdotool
`RL_E2E=1` is a dev-only hook that auto-clicks Allow to simulate the host user; it's ignored in packaged builds (`app.isPackaged`).

## Known limitations
- Verified through the public Render signaling server, but both ends ran on one machine (plus, for 0.2.0, an Android emulator on that machine). No test yet between two physical devices on different networks.
- Render free plan: the signaling service sleeps after ~15 min idle (cold start ~1 min) and has monthly free-hour limits. Builds are unsigned.
- Viewer sends mouse move/click and printable text only (no special keys, scroll, drag, clipboard, file transfer yet).
- Single monitor (primary display). No TURN server deployed (config supported via `ICE_SERVERS`).
- Windows installer/zip are built but have not been run on real Windows. macOS DMG and iOS not built (need a Mac).
- On Wayland Linux, capture goes through the portal picker; injection via nut-js needs X11/XWayland.
