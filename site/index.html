RemoteLink 0.2.0

Transparent, consent-based remote desktop. Open source test release.
Test release, so please read this first. These builds are unsigned. Windows SmartScreen will say "Windows protected your PC" (click More info → Run anyway only if the SHA-256 below matches). This page and the signaling server run on free temporary tunnels from one test computer. They expire after about 2 hours, drop after a few hundred MB of downloads, and come back at a new address. If a download fails, reload this page from its newest address. There is no TURN relay yet, so some networks (strict corporate or carrier NAT) will not connect. macOS and iOS builds are not available yet (they must be built and signed on a Mac).
What RemoteLink does: one computer (the host) shows a 9-digit code. Another device (the viewer) enters it. Nothing is shared until the person at the host clicks Allow. Control of mouse/keyboard is a separate, unticked-by-default checkbox. While a session runs, the host shows a red SESSION ACTIVE banner with an End session button. Either side can end it at any time. Nothing runs in the background or at startup.

How to connect two of your own devices

  1. Install RemoteLink on the computer you want to see or control (the host), and on the device you're connecting from (computer or Android viewer).
  2. Both apps must use the same signaling server. This page's server is:

    Builds downloaded from this page use the address that was current when they were built. If it has changed since, paste the address above into Settings → Signaling server → Save (Android: Settings → Save).
  3. On the host, click Share my screen (Host). A 9-digit code appears. It's valid for 10 minutes and works once.
  4. On the viewer, type the code and click Connect.
  5. On the host, a "RemoteLink connection request" appears. Click Allow. Tick "Also allow control of my mouse and keyboard" only if you want the viewer to control it.
  6. To stop, click End session on either side, or close the app.

Linux hosts: an X11 session is required for screen capture and input (Wayland is untested). macOS hosts (when built) will need Screen Recording and Accessibility permission in System Settings. Phones can be viewers only. iPhone cannot be remote-controlled because iOS provides no API for that.

What has been tested

  • Linux AppImage (packaged) as host ↔ Linux viewer, through this public signaling URL: consent prompt shown, not auto-approved, 29.4 fps at 1280×800, data-channel RTT p50 1.0 ms, view-only correctly blocked input.
  • Android 14 emulator (this APK) as viewer → Linux host via the public URL: live screen at 27 fps, ICE RTT 12 ms, tap-to-click injected on the host, End from phone closed the host session.
  • Signaling over the public wss:// URL: connect 0.15–0.46 s, message RTT p50 29–32 ms / p95 33–41 ms.
  • Second connection request on the host starts with "allow control" unticked again. A bug where it stayed ticked was found and fixed in this build.
  • Not yet tested: two physical devices on different home/mobile networks, Windows on real hardware, the .deb install, macOS, iOS.
