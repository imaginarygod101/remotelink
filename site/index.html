RemoteLink 0.2.1

Transparent, consent-based remote desktop. Open-source test release.
Test release: please read this first. These builds are unsigned. Windows SmartScreen will say "Windows protected your PC". Click More info → Run anyway only if the file's SHA-256 matches the one below. The signaling server runs on Render's free plan. It sleeps after about 15 minutes without use, so the first connection after a quiet period can take about a minute. There is no TURN relay yet, so some networks (strict corporate or carrier NAT) will not connect. macOS and iOS builds are not available yet; they must be built and signed on a Mac.
What RemoteLink does: one computer (the host) shows a 9-digit code. Another device (the viewer) enters it. Nothing is shared until the person at the host clicks Allow. Control of the mouse and keyboard is a separate checkbox that starts unticked. While a session runs, the host shows a red SESSION ACTIVE banner with an End session button. Either side can end it at any time. Nothing runs in the background or at startup.

How to connect two of your own devices

  1. Install RemoteLink on the computer you want to see or control (the host), and on the device you're connecting from (a computer or the Android viewer).
  2. Both apps must use the same signaling server. Builds from this page already use:
    wss://remotelink-signal.onrender.com
    You can check or change it under Settings → Signaling server.
  3. On the host, click Share my screen (Host). A 9-digit code appears. It works once and is valid for 10 minutes.
  4. On the viewer, type the code and click Connect.
  5. On the host, a "RemoteLink connection request" appears. Click Allow. Tick "Also allow control of my mouse and keyboard" only if you want the viewer to control it.
  6. To stop, click End session on either side, or close the app.

Linux hosts need an X11 session for screen capture and input (Wayland is untested). macOS hosts (once built) will need Screen Recording and Accessibility permission in System Settings. Phones can be viewers only. An iPhone cannot be remote-controlled because iOS provides no API for that.

What has been tested (2026-11-25)

  • Packaged 0.2.1 AppImage as host, Linux viewer, through the Render signaling server: consent prompt showed the viewer's real IP and was not auto-approved; with control allowed: 29.1 fps at 1280×800, data-channel RTT p50 1.3 ms, 3 of 3 mouse moves injected.
  • Installed 0.2.1 .deb as host, view-only: 29.1 fps, RTT p50 1.2 ms, viewer input not applied (correct).
  • Signaling round-trip to Render (Frankfurt) from the test machine: connect 372 ms, message RTT p50 104 ms, p95 117 ms.
  • All six release files downloaded from GitHub match SHA256SUMS.txt.
  • Android viewer: 0.2.0 tested on an Android 14 emulator (29.4 fps, tap-to-click). 0.2.1 APK not re-run.
  • Not yet tested: two physical devices on different home/mobile networks, Windows on real hardware, a physical Android phone, macOS, iOS. In every test above, both ends ran on the same machine, so video went directly between them.
